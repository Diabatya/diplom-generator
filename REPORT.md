# REPORT — генератор дипломов/грамот по Excel-списку (итерация 2)

Десктоп-программа для Windows: шаблон (PPTX или PDF) + Excel-список → пакетная
генерация документов с подстановкой данных без изменения дизайна.

Технологии: Python 3.11+, **PySide6**, `python-pptx`, `PyMuPDF`, `openpyxl`,
упаковка `PyInstaller --onefile` (`diplom.spec`). Полностью оффлайн: никаких
сетевых запросов, телеметрии, облачных API.

## 2. Самостоятельные решения

- **PySide6** (LGPL, свободная раздача exe) и **openpyxl** без pandas
  (размер exe ~70 МБ).
- **Измерение ширины текста** — `fitz.Font.text_length` по реальному TTF и
  для PDF, и для PPTX-автоподбора (шрифт ищется по имени семейства в
  системных папках; промах → эвристика 0.55 em/символ).
- **PPTX-превью** — собственный приблизительный рендер на Qt (оффлайн-
  рендера PowerPoint не существует); привязка точная — по координатам
  shape'ов из `python-pptx`.
- **Режимы привязки PPTX** хранятся как `mode: whole|fragment|token` +
  `pattern` (исходный текст блока) + `token` (заменяемая подстрока).
  Отсутствие `mode` в старой разметке = `whole`.
- **PDF-вывод** — `page.insert_text` по базовой линии (ручное выравнивание
  и вертикальное центрирование), т.к. `insert_textbox` молча не рисует
  текст при высоте рамки < ~1.7×font size.
- **Политика существующих файлов**: префлайт-список имён до генерации;
  суффиксный режим ищет первое свободное `имя_new`, `имя_new2`… — поэтому
  нумерация «продолжается» между запусками.
- **Лимит пути 240 символов** (запас от 260): имя файла усекается с учётом
  длины целевой папки.
- **Источник имени файла** — произвольное поле шаблона ИЛИ любой столбец
  Excel (даже не сопоставленный полю), т.к. имя файла логически не обязано
  быть полем подстановки.
- «Все строки пустые» в столбце трактуется как формулы без кэша —
  диагностируется один раз на столбец, а не на строку.
- Общий PPTX — глубокое копирование слайдов с перемаппингом rId внутри
  одной презентации (проверено с картинками).

## 3. Что нужно проверить руками

- **Запуск exe на Windows без Python (P0)**: файл собран на настоящем
  Windows-раннере и выложен в релиз — осталось запустить его на чистой
  Windows-машине и прогнать кейсы. Отдельно проверить на Windows:
  - открытие шаблона и Excel из папки с русскими буквами и пробелами в пути;
  - список шрифтов (должен показать Arial, Calibri, Times New Roman…);
  - автоподбор размера (поведение должно совпадать с macOS-прогоном);
  - генерацию в папку с длинным путём (>200 символов);
  - повторную генерацию в ту же папку (диалог перезаписи).
- **PDF-затирание на реальных шаблонах заказчика**: градиентный/текстурный
  фон, плейсхолдер поверх картинки или линейной графики — там автоподбор
  цвета может дать пятно, а старый текст, нарисованный картинкой/вектором
  (а не текстом), redact не удалит.
- **Общий PPTX на боевых шаблонах с картинками/логотипами**: механизм
  проверен на сгенерированном шаблоне с одним PNG; на реальных файлах
  (несколько картинок, картинки в layout, ссылки) стоит прогнать ещё раз.
- Файлы Excel с формулами — после предупреждения открыть и пересохранить.
- Редкие/несистемные шрифты в PPTX-плейсхолдерах (автоподбор оценочный).

## 4. Как проверить

### Сборка exe на Windows с нуля
**Готовый exe**: релиз `v1.0.0` в приватном репо
`github.com/Diabatya/diplom-generator` → asset `DiplomGenerator.exe`
(~78 МБ, PE32+ x86-64). Собран GitHub Actions на `windows-latest`.

Пересборка: поставить тег `v*` и запушить — workflow соберёт exe и обновит
релиз автоматически. Локально на Windows: `build.bat` →
`dist\DiplomGenerator.exe` (или вручную: `py -3 -m venv .venv`,
`.venv\Scripts\pip install -r requirements.txt`,
`.venv\Scripts\pyinstaller diplom.spec --noconfirm`).

После получения exe на машине без Python проверить: открытие шаблона,
привязку полей, загрузку Excel, пример, генерацию, отчёт.

### Запуск из исходников
`pip install -r requirements.txt` → `python run.py`.

### Тестовые данные и автопроверка
`python make_test_data.py` → `testdata/` (template.pptx с логотипом,
template.pdf, list.xlsx 10 строк с дубликатами, list_bad.xlsx с пустой
ячейкой, list_long.xlsx с длинным ФИО).
`.venv/bin/python tests/headless_test.py` — 54 проверки + метрики PERF
(150 строк: время и память в конце вывода).

### Приёмочные кейсы (шаги в UI)
1. PPTX + 10 строк → 10 файлов, дизайн неизменен.
2. PDF + дубликаты → `Иванов.pdf`, `Иванов_2.pdf` (если столбец содержит
   только фамилии; выберите его в «Поле для имени файла»).
3. Два поля, ФИО привязано к двум местам.
4. `list_bad.xlsx` → предупреждение о пустой ячейке до генерации.
5. `list_long.xlsx` → автоуменьшение шрифта, строка в отчёте.
6. «Один общий файл» → один файл с N слайдов/страниц по порядку.
7. `.mapping.json` — предложение загрузить при повторном открытии.
8. exe на чистой Windows — инструкция выше; **проверяется вручную**.

### Новые проверки итерации 2
- **Перезапись**: сгенерируйте в папку, затем запустите генерацию туда же —
  диалог с тремя вариантами; проверьте `_new`-суффиксы и отчёт.
- **Имя файла**: на шаге 2 переключите «Поле для имени файла» на «Столбец:
  Регион» → файлы `Москва.pptx`, `Казань_2.pptx`…
- **Фрагмент**: привяжите блок «Награждается Фамилия Имя Отчество за
  победу», выберите режим «фрагмент» и укажите «Фамилия Имя Отчество» →
  остальной текст блока сохранится.
- **Листы**: Excel с двумя листами → выбор листа на шаге 2.
- **Пустой столбец/формулы**: Excel, где столбец пуст целиком → отдельная
  подсказка про формулы.
- **Пример (PDF)**: диалог показывает шаблон и результат рядом.

## 5. Известные ограничения

- **exe на Windows не собран и не проверен** — сборка валидирована только
  конфигурацией spec и аналогичной сборкой на macOS; см. раздел 3.
- PPTX-превью приблизительное (повороты, градиенты, WordArt, SmartArt не
  отображаются); на генерацию не влияет.
- В режимах «фрагмент/токен» форматирование берётся от первого run'а блока:
  если внутри блока разные шрифты, итог будет одним шрифтом.
- Автоподбор — по ширине одной строки (или самого длинного слова при
  включённом переносе), многострочная высота не подбирается.
- PDF: кириллица требует TTF (по умолчанию ищется Arial/DejaVu в системе).
  Вставленный текст при копировании из PDF даёт неразрывные пробелы и
  «мягкие» дефисы — особенность PyMuPDF, визуально корректно.
- Excel: учитывается формат `00000`; другие числовые форматы берутся «как
  хранится». `data_only=True` — формулы без кэша читаются как пустые
  (диагностируется отдельным сообщением).
- Производительность замерена на 150 строках (PPTX ~1.1 с, PDF ~4 с,
  ~111 МБ, macOS arm64); на Windows с антивирусом запись файлов может быть
  медленнее — для сотен строк ориентируйтесь на десятки секунд.
- Привязка кликом работает по блокам верхнего уровня; блоки внутри групп —
  через список блоков.

## 6. Точки расширения

- Несколько токенов/полей внутри одного блока PPTX.
- DOCX-шаблоны (та же модель полей).
- Точный рендер PPTX-превью через локальный LibreOffice, если установлен.
- Многострочный/вертикальный автоподбор для PDF-рамок.
- Запоминание маппинга Excel между запусками; drag&drop файлов.
- Автотест Windows-сборки в CI (GitHub Actions windows-latest + PyInstaller).
