# REPORT — генератор дипломов/грамот по Excel-списку (итерация 7)

Десктоп-программа для Windows: шаблон (PPTX или PDF) + Excel-список → пакетная
генерация документов с подстановкой данных и сохранением структуры шаблона.
Визуальная идентичность в Microsoft PowerPoint без ручной проверки не заявляется.

Технологии: Python 3.11+, **PySide6**, `python-pptx`, `PyMuPDF`, `openpyxl`,
упаковка `PyInstaller --onefile` (`diplom.spec`). Полностью оффлайн: никаких
сетевых запросов, телеметрии, облачных API.

## 2. Самостоятельные решения

- **PySide6** (LGPL, свободная раздача exe) и **openpyxl** без pandas
  (размер exe ~80 МБ).
- **Измерение ширины текста** — `fitz.Font.text_length` по реальному TTF и
  для PDF, и для PPTX-автоподбора (шрифт ищется по имени семейства в
  системных папках; промах → эвристика 0.55 em/символ).
- **PPTX-превью** — собственный оффлайн-рендер на Qt: фон слайда
  (slide→layout→master, включая `bgRef` и цвета темы), декоративная
  графика layout/master и собственные фигуры слайда; повороты, WordArt и
  SmartArt по-прежнему не отображаются — пометка «приблизительный»
  остаётся. Привязка точная — по координатам shape'ов из `python-pptx`.
- **Режимы привязки PPTX** хранятся как `mode: whole|fragment|token` +
  `pattern` (исходный текст блока) + `token` (заменяемая подстрока).
  Отсутствие `mode` в старой разметке = `whole`.
- **Run-aware замена фрагмента**: перед заменой вычисляется покрытие
  фрагмента run'ами (по накопленным длинам текста); run'ы внутри фрагмента
  удаляются, начальный run делится на «до/замена/после» через клонирование
  `<a:r>` и копирование `rPr`. Разные форматы внутри фрагмента → формат
  первого + пометка в отчёте.
- **PDF-вывод** — `page.insert_text` по базовой линии (ручное выравнивание
  и вертикальное центрирование), т.к. `insert_textbox` молча не рисует
  текст при высоте рамки < ~1.7×font size.
- **PDF-заливка фона** — по умолчанию медиана пикселей по краям рамки
  (плотная рамка по тексту работает); при риске «дыры» в цветной плашке
  (края светлее внутренности на >0.25 яркости) — предупреждение в UI и в
  отчёте, а цвет можно задать вручную или пипеткой (`fill_color`,
  хранится в `.mapping.json`).
- **Единые суффиксы `_N`**: функция подбора имени ищет первое свободное
  `имя`, `имя_2`, `имя_3`… — одинаково для дублей внутри пачки и для
  существующих файлов; нумерация «продолжается» между запусками.
- **Лимит пути 240 символов** (запас от 260): имя файла усекается с учётом
  длины папки и конечного суффикса; невозможный путь выдаёт ошибку, а не цикл.
- **Источник имени файла** — произвольное поле шаблона ИЛИ любой столбец
  Excel; опция «только первое слово» применяется к выбранному значению до
  дедупликации.
- «Все строки пустые» в столбце трактуется как формулы без кэша —
  диагностируется один раз на столбец, а не на строку.
- Общий PPTX — копирование слайдов и собственного фона (цвет/градиент/
  изображение), перемаппинг rId, порядок по строкам; по умолчанию один
  слайд диплома на строку (если в шаблоне несколько — выбор в шаге 1).
- **CI**: тесты и сборка в одном job — exe выкладывается только если тесты
  зелёные; `PYTHONUTF8=1` на Windows-раннере (cp1252 не печатает кириллицу
  из тестов); метрики памяти — `tracemalloc` (кроссплатформенно, `resource`
  отсутствует на Windows). После сборки сам exe запускается с `--selftest`
  — ловит отказы onefile-упаковки (hidden imports, Qt-плагины, DLL),
  которые сборка не показывает.
- **Кэш шрифтов**: список файлов и stem-мапа резолва имён кэшируются
  (`lru_cache`); на Windows `C:\Windows\Fonts` — сотни файлов, обход
  при каждом замере был главным тормозом (~2.2x ускорение в CI).
- **`--selftest` без GUI и без testdata/**: фикстуры создаются во
  временной папке самим бинарём; вывод дублируется в `selftest_result.log`
  (у GUI-subsystem exe нет консоли — CI забирает лог-файл и код возврата
  через `Start-Process -Wait`).

4. `list_bad.xlsx` → предупреждение о пустой ячейке до генерации.
5. `list_long.xlsx` → автоуменьшение шрифта, строка в отчёте.
6. «Один общий файл» → один файл с N слайдов/страниц по порядку.
7. `.mapping.json` — предложение загрузить при повторном открытии.
8. exe на чистой Windows — артефакт CI; `--selftest` прогнан в CI,
   **открытие GUI проверяется вручную по `WINDOWS_CHECKLIST.md`**.

### Новые проверки итерации 3
- **Первое слово**: на шаге 2 выберите поле ФИО + галочку «только первое
  слово» → превью «Пример: Иванов.pdf», файлы `Иванов_2.pdf`…
- **Единые суффиксы**: сгенерируйте в папку, затем туда же ещё раз с
  режимом «суффикс» → `Иванов_2.pdf`, `Иванов_3.pdf` (не `_new`).
- **Фрагмент с форматированием**: в PPTX-блоке «Награждается **Фамилия Имя
  Отчество** за победу» (ФИО крупнее/жирнее) привяжите фрагмент → замена
  возьмёт крупный шрифт, «Награждается … за победу» сохранит свой.
- **Смешанные run'ы**: фрагмент через два run'а с разными шрифтами →
  пометка в `generation_report.txt`.

### Новые проверки итерации 5
- **Цветная плашка (PDF)**: шаблон, где плейсхолдер лежит на цветной
  плашке → обведите рамку с запасом → появится предупреждение →
  пипеткой возьмите цвет плашки → «Сгенерировать пример» → плашка без
  дыры.
- **Нестандартные маркеры**: блок «Диплом № <номер>» → в диалоге
  привязки варианта «токен» нет; заменить `<номер>` можно через режим
  «фрагмент».
- **Повторный токен**: блок «@@FIO@@ … @@FIO@@» → оба вхождения заменены
  одинаковым шрифтом, автоподбор не занижен.

## 5. Известные ограничения

- **GUI-запуск exe на реальном Windows-десктопе не проверялся** — CI
  собирает exe, гоняет headless-проверки и `--selftest` самого
  бинаря на `windows-latest`, но интерактивный запуск окна требует
  ручной проверки по `WINDOWS_CHECKLIST.md` (раздел 3).
- PPTX-превью приблизительное (повороты, градиенты, WordArt, SmartArt не
  отображаются); на генерацию не влияет.
- PDF-заливка «авто» корректна только для плотной рамки по тексту; при
  рамке «с запасом» поверх цветной плашки автоматика оставляет светлую
  дыру — программа предупреждает и предлагает пипетку, но глазами
  проверить стоит. На градиентном/текстурном фоне любая заливка — пятно.
- В режиме «фрагмент» форматирование берётся от run'а в начале фрагмента;
  если внутри самого фрагмента разные шрифты — используется первый,
  строка помечается в отчёте. В режиме «токен» формат — от run'а,
  содержащего токен.
- PPTX-автоподбор оценивает высоту, переносы и межстрочный интервал,
  но без установленного шрифта и без рендерера PowerPoint это лишь
  приближение; такие строки помечаются для ручной проверки.
- PDF: кириллица требует TTF (по умолчанию ищется Arial/DejaVu в системе).
  Вставленный текст при копировании из PDF даёт неразрывные пробелы и
  «мягкие» дефисы — особенность PyMuPDF, визуально корректно.
- Excel: учитывается формат `00000`; другие числовые форматы берутся «как
  хранится». `data_only=True` — формулы без кэша читаются как пустые
  (диагностируется отдельным сообщением).
- Производительность: 150 строк — PPTX ~1.4–2.1 с / PDF ~4.1–5.2 с на
  dev-машине (macOS arm64); на CI-раннере ~8.1 / ~14.0 с после кэша
  шрифтов (до кэша — 17.9 / 22.1 с). На пользовательской Windows с
  антивирусом ориентируйтесь на десятки секунд.
- Блоки внутри групп доступны кликом/списком, таблицы адресуются по
  ячейкам; SmartArt/WordArt и точная PowerPoint-раскладка не поддерживаются.

## 6. Точки расширения

- Несколько токенов/полей внутри одного блока PPTX.
- DOCX-шаблоны (та же модель полей).
- Точный рендер PPTX-превью через локальный LibreOffice, если установлен.
- Многострочный/вертикальный автоподбор для PDF-рамок.
- Постоянное хранение сопоставления Excel между перезапусками; drag&drop файлов.
- Автовыкладка релиза по тегу есть в `build-windows.yml`; можно добавить
  ночные сборки или сборку по PR.
